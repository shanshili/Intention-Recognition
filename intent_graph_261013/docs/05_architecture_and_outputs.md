# 代码组织、复用与运行产物

## 1. 组织原则

模型变化不应同时改变数据窗口、目标 mask、基线分母或评价单位。新目录将数据协议、模型、训练与评价分开，使同一数据对象可以顺序运行多个模型、多个训练种子与多种损失配置。

实现文件含代码；本文只说明模块责任、数据对象的数学形状与产物含义，不嵌入代码片段或运行命令。

## 4. 共用数据对象与 batch

准备后的基础数据包括原始矩阵、原始观测指示、标准化目标、填补后的特征、训练均值与标准差、坐标、节点 ID、时间网格、三分区窗口原点、固定候选图与协议 ID。

在一批 $B$ 个窗口中，共用数据形状为

$$
\begin{aligned}
\text{历史}&\in\mathbb R^{B\times W\times N\times F},\\
\text{最新水平值}&\in\mathbb R^{B\times N},\\
\text{标准化目标}&\in\mathbb R^{B\times N\times H},\\
\text{目标有效指示}&\in\{0,1\}^{B\times N\times H}.
\end{aligned}
$$

其中 $F$ 为启用后的节点特征通道数。每个 batch 还保留窗口原点与目标时间。启用平滑时，附加真实前序历史和前序配对有效指示，而不依赖当前批次随机顺序。

候选边在准备数据阶段固定。每条边的源、目标索引及其顺序由同一个图对象提供，模型不自己重建不同 KNN 图。

## 5. 统一模型能力

模型接收共同数据并提供预测：

$$
\hat Y\in\mathbb R^{B\times N\times H}.
$$

图模型可提供门控

$$
A\in[0,1]^{B\times E},
$$

以及实际传播系数

$$
\tilde a_{ij}^t=\frac{a_{ij}^t}{\max(1,d_j)}.
$$

门控与实际传播系数不能混淆；后者还受目标节点入度影响。没有图的模型不提供门控。模型声明是否支持边排名与边干预，评价据此选择适用分量。

Persistence 的拟合为空操作；Ridge-AR 直接拟合线性系数；神经模型使用共同训练器。统一接口不意味着所有模型必须使用反向传播，也不要求无需训练的模型伪造训练损失曲线。

## 6. 运行独立性与复用

每次运行记录模型名、协议 ID、训练种子、展开模型和损失参数、实际数据范围与运行时间。相同协议的数据准备在一次模型组运行中共用，不同模型独立拟合并保存各自状态。恢复最佳状态后，同一模型分别推断训练、验证和测试窗口，三分区数据与模型状态保持可追溯。

模型初始化使用独立种子上下文，避免运行顺序改变下一个模型的参数。训练批次排列由训练种子与 epoch 决定；评价按稳定窗口原点顺序执行。

大数组采用按需窗口与压缩产物。数据指纹用于确认来源，窗口 ID 用于确认评价对象，不能只用一个目录名判断实验相同。

神经模型默认自动选择 CPU 或 CUDA。模型状态和运行摘要记录实际设备；设备选择与模型定义分别保存。使用相同种子和相同配置可以重建初始化与批次安排，但 GPU 聚合、浮点求和顺序和不同运行库不保证逐位一致。

## 7. 应保存的运行产物

产物分为数据协议、模型状态、预测、门控与指标几个方面。具体文件由统一产物模块生成，含义如下：

| 产物 | 必须能恢复或判断的信息 |
|---|---|
| 展开数据协议 | 路径、内容指纹、节点顺序、实际时间范围、切分、标准化、特征与候选边 |
| 展开实验配置 | 模型参数、训练参数、损失权重、训练与干预种子、评价版本 |
| 模型状态 | 已选择的最佳神经参数或 Ridge 系数；Persistence 无需参数状态 |
| 训练历史 | 每轮训练分量、有效目标数、完整验证 MAE、最佳轮次和提前停止情况 |
| 预测数组 | 每窗口、节点、horizon 的预测、真实目标、目标 mask 与最新输入 |
| 窗口元信息 | 原点、目标时间、节点顺序以及分区 |
| 门控产物 | 支持模型的连续门控、候选边顺序、分布诊断与门控类型 |
| 预测指标 | 原始单位与标准化 MAE/RMSE、各 horizon、Persistence 与 Skill |
| 边干预指标 | 各预算 Top/Low/Random 的绝对 MAE、差值、随机标准差与校正效应 |
| 时间诊断 | 逐窗口误差、相邻 Top-K Jaccard、连续门控变化与空图状态 |
| 图表 | 训练曲线、各 horizon MAE、少量门控图与删除效果展示 |

新运行分别保存三个分区的预测、门控、逐窗口误差与分区诊断。默认只有测试分区执行边干预与生成图表；训练、验证完整数值数组仍保存。旧运行缺少的分区文件不会由新目录结构自动补全。

门控分数默认保存为压缩数组。全量数据和多种子结果仍可能占用明显空间，因此图示数量与原始连续分数保存策略可以分别控制；任何关闭保存的选择都应出现在运行配置中，不能只保留选择性展示的图而隐藏完整评价。

### 7.1 具体运行层级与文件

一个模型组运行保存到 `outputs` 下的时间戳目录，例如以 `suite_` 开头的目录。组级文件 `protocol.json` 保存展开数据协议，`data_metadata.json` 保存实际数据范围与来源假设，`suite_data.npz` 保存共用数据与对齐信息，`suite_summary.json` 汇总所选模型和种子的运行状态。完整结束后生成 `comparison.json` 和 `comparison.csv`，按模型与展开配置汇总测试结果；额外分项汇总表见下文。

组目录内按模型和训练种子继续分层。新运行使用三分区产物布局，每个模型、每个种子的根目录保存：

| 文件 | 含义 |
|---|---|
| `resolved_config.json` | 展开模型、训练和评价配置，包括设备要求 |
| `run_summary.json` | 协议、评价、拟合、测试兼容主指标以及三分区结果与文件路径 |
| `training_history.json` | 训练／拟合历史与最佳状态说明 |
| `split_metrics.json` | 训练、验证、测试的完整指标与状态 |
| `per_seed_summary.csv` | 当前模型种子的三个分区各一行 |
| `model.pt` 或模型状态 `.npz` | 可选，神经参数或线性系数状态；Persistence 不伪造模型参数 |
| `model.json` | Persistence 的方法说明，不是可训练参数 |

完整分区产物位于 `splits/train`、`splits/val` 和 `splits/test`：

| 分区内文件 | 含义 |
|---|---|
| `predictions.npz` | 本分区全部预测、原始目标、mask、窗口与时间对齐数组 |
| `edge_scores.npz` | 可选，图模型本分区完整连续门控和边对齐信息 |
| `resolved_config.json` | 分区实际评价配置与共享实验配置 |
| `training_history.json` | 对应同一模型的训练历史 |
| `run_summary.json` | 本分区明确标记的预测、图诊断与评价状态 |
| `per_window_metrics.csv` | 窗口原点、目标时间、有效目标数与模型／持续性误差 |
| `graph_evaluation.json` | 图能力适用性、各预算干预与门控诊断 |
| `graph_evaluation.npz` | 可选，逐窗口干预及动态诊断数组 |
| `figures` | 默认仅测试分区生成训练图、各 horizon MAE、门控图与删除差值图 |

新布局不在模型种子根目录重复保存测试预测大数组。根摘要中的主预测指标继续代表测试分区，便于兼容测试结果比较；三分区详细指标和数组路径通过分区结果记录查找。只有全部分区产物保存完成后，该模型种子的根摘要才标记完成。

产物属于这次确定的数据协议与评价配置，不能从另一次运行随意拿门控文件配合本次目标。文件的实际键名和数组形状以保存的元信息为准。

当前比较产物是 JSON 与 CSV 汇总，没有另行实现组级模型比较图或候选图独立展示。门控空间图使用节点坐标与有向边；候选边本身保存在共用数值产物中。

### 7.2 模型组结果表

| 组级文件 | 行的含义与主要内容 |
|---|---|
| `comparison.json`、`comparison.csv` | 相同配置的模型种子测试指标汇总，包含均值与训练种子标准差 |
| `prediction_summary.csv` | 模型、种子、分区对应的 MAE／RMSE、标准化误差、Skill 与有效目标数 |
| `horizon_summary.csv` | 模型、种子、分区、未来步对应的误差与有效目标数 |
| `graph_summary.csv` | 模型、种子、分区、预算对应的 Top／Low／Random 删除和保留及状态 |
| `diagnostics_summary.csv` | 门控分布、零分、近零、相邻变化、阈值密度与空图比例 |
| `efficiency_summary.csv` | 参数量、拟合与各分区预测耗时、最佳轮次、泛化差距和实际设备 |
| `report_manifest.json` | 报告覆盖分区、完成运行数、各表行数、空值与两层标准差定义 |

这些表为同一模型组提供集中入口，不替代逐窗口数组。预测、horizon、图与诊断表按分区展开；效率表每个模型种子一行，在该行列出三分区耗时与差距。没有图能力与默认未执行训练、验证干预分别注明原因，空值不能被自动补为零。详细解释见 [三分区保存与结果汇总](08_result_summaries.md)。

## 8. 比较已有运行

严格可比较结果必须满足

$$
\begin{aligned}
\operatorname{protocol\_id}^{(1)}&=
\operatorname{protocol\_id}^{(2)},\\
\operatorname{evaluation\_signature}^{(1)}&=
\operatorname{evaluation\_signature}^{(2)},\\
\mathcal T_{te}^{(1)}&=\mathcal T_{te}^{(2)},\\
M_{te}^{(1)}&=M_{te}^{(2)}.
\end{aligned}
$$

候选边顺序与评价设置也需要一致，特别是 Top-K 取整、随机种子、分数阈值和干预范围。模型参数与损失权重可以不同，因为这些正是比较对象。

比较程序只合并相同数据协议与评价签名的运行；每个模型、每个训练种子的独立结果继续可查。跨协议可以阅读各自结果，但不输出误导性的统一优劣名次。

当前严格比较要求传入的运行数据协议 ID、评价签名和实际有序目标指纹全部一致，不一致时拒绝合并。指标还检查保存的窗口总数与有效目标总数，避免摘要和数组不一致。相同模型与相同训练配置按配置签名汇总，重复神经训练种子拒绝合并；确定性基线的重复记录只计一次有效结果，标准差为空。

对新三分区运行，还核对相应分区的保存路径、目标指纹与指标。历史仅测试集运行可以据已有测试证据比较，但训练、验证与泛化差距记为未保存，报告清单说明分区覆盖不完整，不从其他运行借用分区结果。

不同模型的门控数值尺度未校准，因此不能直接比较平均门控大小认定哪个模型“意图更强”。主要比较完整预测、Skill、Top 相对 Random/Low 的效果，以及多种子是否稳定。

## 9. 后续扩展的接入位置

新增模型应复用同一准备数据和评价对象，声明其能力，提供统一预测输出；模型专属训练可以接入独立拟合分支。新增特征归入数据协议，新增损失归入训练配置，新增指标进入评价版本。

旧 DEIG 或 Graph WaveNet 接入后，应明确其空间传播路径、门控定义以及干预作用范围，不能用基本模型的“唯一空间消息路径”解释套到多层图模型上。

合成数据未来作为另一种明确的数据来源接入，增加真实边标签和候选覆盖检查。它与真实交通任务共享预测、窗口和结果组织，但结构真值指标只在具有真值时启用。
