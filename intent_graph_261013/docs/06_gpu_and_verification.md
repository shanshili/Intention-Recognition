# GPU、显存与验证约定

## 1. 设备选择与算法一致性

当前目标硬件为 NVIDIA RTX 4060 Ti，显存 8 GB。神经模型默认自动选择计算设备：

$$
\operatorname{device}=
\begin{cases}
\operatorname{CUDA},&\text{PyTorch 能访问可用 CUDA 设备},\\
\operatorname{CPU},&\text{否则}.
\end{cases}
$$

明确要求 CPU 时使用 CPU；明确要求 CUDA 但 CUDA 不可用时给出环境错误，不静默回退。数据读取、训练期统计、候选图构造、Persistence 与 Ridge-AR 仍由 CPU 执行。

GPU 上的模型仍是同一个函数：

$$
\hat Y=f_\theta(X,E_0,A),
\qquad
\theta\leftarrow\operatorname{Adam}(\theta,\nabla_\theta\mathcal L).
$$

计算设备不增加历史信息、不改变损失分量，也不会自行提高识别可信度。它的主要作用是加速张量计算，使同一协议下运行多模型和多种子更方便。

已核验的现有运行环境位于 `C:/Users/123/AppData/Local/Programs/Python/Python310/python.exe`，使用 Python 3.10.0、PyTorch 2.7.1+cu118、CUDA 运行库 11.8。RTX 4060 Ti 可用，实际神经模型已经在 CUDA 上完成小型训练与评价。本框架复用该环境，无需重新安装 PyTorch。

运行摘要记录实际加载版本和设备信息；安装文件版本本身不能证明 CUDA 计算已经成功，应以实际张量运算与模型验证为证据。额外 CPU 验证环境可用于交叉检查基础模块，但不是默认神经运行环境。

当前神经模型使用单精度浮点计算，没有启用自动混合精度。模型先在 CPU 上使用匹配种子初始化共同部件，再移到指定设备，避免不同设备的初始化方式成为额外变量。

## 2. 显存占用由什么决定

令 batch 大小为 $B$，历史长度为 $W$，节点数为 $N$，特征数为 $F$，候选边数为 $E$，编码维度为 $d$，消息维度为 $m$。单精度张量每个元素通常为 4 字节，主要输入与门控张量规模近似为

$$
\begin{aligned}
S_{input}&\approx4BWNF,\\
S_{node}&\approx4BNd,\\
S_{pair}&\approx4BE(4d),\\
S_{message}&\approx4BEm.
\end{aligned}
$$

这些只是主要张量的直接存储估计，不包含全部中间激活、反向传播缓存、优化器状态、运行库工作区和内存分配开销。DynamicGate 的逐边配对表示可能比节点表示更显著；候选图变稠密会增加 $E$ 并放大这部分成本。

Adam 还保存参数的一阶、二阶状态，训练需保存梯度与反向传播信息，因此训练通常比不计算梯度的评价更耗显存。默认训练 batch 为 32，评价 batch 为 128；本项目的初级网络较小，但实际显存仍应由运行测量确认。

显存不足时优先降低 batch 大小，保持节点、时间范围、horizon 与全部评价目标不变。不得通过丢弃尾批或仅评估少量窗口规避显存问题。训练 batch 大小会改变优化路径，应保存展开设置；评价 batch 大小主要影响吞吐与求和顺序，不改变样本集合。

## 3. 种子与数值复现边界

模型种子控制初始化与训练批次安排。独立模型种子与随机干预种子分别保存。相同初始化和相同批次不意味着跨设备完全相同的数值轨迹：

$$
f_{\theta}^{CPU}(X)
\approx f_{\theta}^{CUDA}(X).
$$

通常应在合理浮点容差内比较，而不是要求逐位相等。并行消息聚合与求和顺序、底层运行库和不同设备可能带来细微差别，这些差别经多轮优化也可能产生不同最佳 epoch。

默认关闭严格确定性。若开启严格确定性，PyTorch 可以对缺少确定性实现的 CUDA 操作报错；这不是数据或数学模型错误。不能静默关闭该设置并声称获得严格确定性的结果。

不把 CPU 结果与 CUDA 结果混成“完全相同重复”来缩小误差条。正式比较尽量使用同一设备与同一软件环境，并记录实际环境；结果可信度仍由完整预测、多训练种子和随机干预对照决定。

## 4. 验证证据应分层记录

| 检查层次 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 模块语法和导入 | 文件可解释、所需库可加载 | 算法效果良好 |
| CPU 小型数据检查 | mask、时间切分、尾批和基线公式符合约定 | CUDA 训练可用 |
| CUDA 张量运算 | 当前 PyTorch 能实际使用设备 | 多模型端到端都正确 |
| 神经模型小型检查 | 门控形状、固定入度、梯度和设备迁移正常 | 真实交通动态结构可信 |
| 小型端到端运行 | 入口、训练、评价、保存与比较联通 | 全量数据正式结论 |
| 开发及全量实验 | 指定协议上的预测和干预证据 | 无真值的物理因果结论 |

每份验证结果标明实际环境、已完成范围以及被跳过的检查。某环境未安装 PyTorch 时跳过神经检查，只代表缺少执行条件；不能将“跳过”报告为测试已经通过。安装 CUDA 构建后也应重新执行原来未完成的神经检查。

第一版验证重点是有实际含义的数学约定：目标不跨分区、未来不参与补值、原始缺失目标不计分、尾批不丢失、固定候选入度在干预后不变、随机标准差来自种子整体指标，以及无图模型不伪造排名。

性能计时只在同一硬件和相似运行条件下比较。GPU 的异步执行与首次加载可能影响表观时间；模型拟合耗时、预测耗时与整组运行耗时分别说明，避免将环境初始化时间误作模型本身成本。
