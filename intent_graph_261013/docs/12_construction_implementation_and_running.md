# 构建实验实现、训练输出与正式运行

## 1. 已实现的模型范围

本轮实现文档1第3节的增量构建链。保留 B1–B6，新增 M1–M7；M0 是 B6／DynamicGate 的别名，输出目录沿用 dynamic_gate。入口接受大小写的 B1–B6、M0–M7 或原模型名称。同一次运行若同时选择 B6 和 M0，会明确报重复，避免训练两次相同模型。

| 版本 | 入口名称 | 输入 | 前置空间编码 | 时间表示 | 评分器附加信息 |
|---|---|---|---|---|---|
| B1 | persistence | 最近流量 | 无 | 无训练 | 无 |
| B2 | ridge_ar | X1 | 无 | 节点历史线性回归 | 无 |
| B3 | local | X1 | 无 | 历史 MLP | 无 |
| B4 | fixed_graph | X1 | 无 | 历史 MLP | 全一候选门控 |
| B5 | static_gate | X1 | 无 | 历史 MLP | 每边静态参数 |
| B6＝M0 | dynamic_gate | X1 | 无 | 历史 MLP | 动态节点对 |
| M1 | m1 | X1 | 普通 GAT | 历史 MLP | 动态节点对 |
| M2 | m2 | X1 | 普通 GAT | TCN 末端 | 动态节点对 |
| M3 | m3 | X7 | 普通 GAT | TCN 末端 | 动态节点对 |
| M4 | m4 | X7 | 普通 GAT | TCN 末端 | 再加静态边 e |
| M5 | m5 | X7 | 边感知 GAT | TCN 末端 | 静态边 e |

这不是完整母模型的全部单组件消融实现；本轮首先实现上述构建版本，全部默认只采用 Huber 预测损失。原有稀疏、方向和时间损失开关仍存在，第一轮构建建议保持权重为0。

## 2. 共同协议及初步实现约定

用户确认原始数据起点为 2025-01-01 00:00:00。新构建协议记录 timestamp_source 为用户确认起点的规则网格，保留五分钟步长，不伪称从源文件读到时间列或完成了独立缺步核验。

先统一准备7个通道，再按模型截取 X1 或 X7。通道顺序为流量、变化率、周期残差、日内 sin/cos、星期 sin/cos。周期残差按星期×小时，由训练期有效观测均值计算。

所有模型共享原始预测目标、目标 mask、窗口原点、候选图、标准化统计及公共协议身份。运行保存的 effective feature_channels 与 input_features 明确模型实际使用的信息；run_summary 的 construction 段记录各新增模型的组件和感受野。

GAT 为单头、有向、逐历史时刻聚合，对每个接收节点的入边及内部自身通道做 softmax。自身通道不进入候选意图边集合，也不参与 Top-K 排序。

M2–M7 统一使用三层因果卷积，核长3、扩张率1、2、4，感受野

$$
R=1+(3-1)(1+2+4)=15.
$$

默认 W=12，全部历史可被末端表示访问。若增加 W，必须同时调节所有 TCN 版本的卷积设置，使 R≥W；实现会拒绝不足感受野。

后置消息全部采用固定候选入度：

$$
g_j^t=\frac1{\max(1,d_j)}\sum_{i:(i,j)\in E_0}s_{ij}^t W_m z_i^t.
$$

默认动态边特征保留原方案基本定义，没有加入相关收缩或其他统计强化。常量序列、无足够历史等基本数值情况回退为0，防止非有限值；正滞后搜索仍可得到负相关。趋势只统计窗口内部 W−1 个变化，不把首个变化对应的窗口外时刻算进去。

新增模型的现有图干预仅关闭后置消息；前置 GAT 保持工作，结果 scope 明确记录为 post_message_only。全空间路径的联合干预尚未实现，不能把后置筛选图当作全模型唯一依赖图。

## 3. 正式运行入口

run_construction.py 和 run_construction.ps1 是新构建实验入口。PowerShell 脚本沿用已验证的 Python 3.10 解释器，避免系统中其他 Python 环境缺少 CUDA；INTENT_GRAPH_PYTHON 可显式指定另一个解释器。

入口默认使用 configs/experiments_construction.json 和 configs/protocol_construction_dev.json。未选择 models 时，会运行13个不同模型，B1/B2各一次，11个神经模型各3种子，共35次运行；M0不会另外增加一次。

只想做 M0–M7 构建链时，选择 M0 到 M7 即可，共8个神经模型、默认24次运行。单独 M7 或某个种子也可通过同一入口选择。原 run_experiment.py／run.ps1 仍默认运行旧六模型配置。

| 协议文件 | 数据范围 | 用途 |
|---|---|---|
| protocol_construction_smoke.json | 前576个时刻，2天 | 检查代码和设备，不作为有效性结论 |
| protocol_construction_dev.json | 前8640个时刻，30天 | 默认构建开发比较 |
| protocol_construction_full.json | 全部输入CSV时刻 | 全量实验；保持同一时间切分规则 |

入口帮助给出可直接使用的命令行选项。选择 protocol、models、seeds、device、epochs、patience 等参数即可调整单次运行，完整命令在聊天交付中提供，文档不放代码或命令。

## 4. epochs 与早停怎么修改

长期默认值在 configs/experiments_construction.json 的 training 部分；命令行同名选项覆盖本次默认，并保存到 resolved_config，后来编辑文件不会改变历史运行。

| 配置字段／入口选项 | 默认 | 作用 |
|---|---|---|
| epochs | 100 | 最大实际训练轮数 |
| patience | 15 | 连续多少轮没有足够验证改善时早停 |
| min_delta／min-delta | 0 | 标准化验证 MAE 的最小改善量 |
| batch_size／batch-size | 32 | 神经训练批大小 |
| learning_rate | 0.001 | 配置文件中的学习率 |
| seeds | 0、1、2 | 独立神经训练种子 |
| device | auto | CUDA可用时GPU，否则CPU；正式可显式选cuda |

最佳状态只按完整标准化验证 MAE 选择。若当前验证误差为 Lval，已记录最佳为 Lbest，则仅在

$$
L_{val}<L_{best}-\delta
$$

时更新最佳模型并重置早停计数；否则计数加1。达到 patience 后停止并恢复最佳状态。测试误差从不参与该决定。

epochs 不是保证执行轮数。要尽量运行满100轮，可把 patience 设为至少100；patience 必须为正，0不表示关闭早停。initial epoch0 的持续性状态也参与选模，best_epoch=0 不等于没有执行训练。

## 5. 每个 epoch 的控制台输出

所有神经模型共享同一训练器，每轮即时输出模型、种子、当前轮／上限、预测损失、稀疏／方向／时间分量、总训练损失、验证预测损失、标准化验证 MAE、最佳轮次、未改善轮数／patience及本轮耗时。即使损失权重为0，也明确打印0。

训练损失按批内有效目标加权汇总，描述本轮不同批次的优化过程；验证损失和 MAE 对同一轮结束后的完整验证分区计算。两者不能拿数值大小直接判断过拟合，尤其 Huber 与 MAE 不是同一量。

epoch0 没有优化批次，训练损失记为 N/A，仅展示初始化验证指标。Persistence 无训练轮；Ridge 使用闭式求解，无 epoch，但打印各正则候选的验证 MAE。不会为这些基线制造虚假的轮数。

每轮记录同时写入 training_history.json；效率表保留 requested_epochs、actual_epochs、best_epoch、stopped_early、patience和min_delta，便于解释配置上限与实际结束轮数的差异。

## 6. 保存、绘图与运行成本

结果继续写入新的 outputs/suite_时间戳 目录。每个模型／种子完整保存 train、val、test 预测和适用的门控；模型组汇总保持公共目标指纹一致性检查。

构建配置默认训练后自动保存测试集前10个相邻窗口的PNG图、拼图、候选图和密度曲线。图设置在 evaluation.sequence_plots；也可使用 sequence-plots 参数指定独立JSON。no-plots关闭图像保存，数值结果仍保存。

默认测试图干预含3个预算，每预算20个随机种子的删除与保留，还包含Top／Low和全消息关闭，计算成本可能超过单次预测或小规模训练。skip-interventions适合代码检查；正式评估要保留干预，不能把跳过后空白结果理解为0。

## 7. 已完成的验证

新增行为测试覆盖模型矩阵、GAT方向及自身路径、e注入位置、TCN因果性与最早历史访问、动态特征、M7注意力归一、梯度、后置掩码、空图和保存设备。数据视图与运行测试检查共同目标、别名去重、逐轮日志和三分区保存。

原有与新增回归检查共76项通过（74项完整回归，加随后新增的2项构建运行集成检查）。使用用户现有Python3.10及PyTorch环境完成验证。

实际两天GPU检查已对13个不同模型各做一个种子、两轮神经训练，运行目录为 suite_20261015_021446_895874；全部三分区指纹一致，新模型M2–M7记录R=15。

另以128个时刻、M7一种子、两轮，检查删边／留边、两随机种子和自动连续绘图，运行目录为 suite_20261015_021858_505742。这些是实现验证，并未执行100轮、多种子的正式全量实验。

两轮检查中神经模型均恢复epoch0，不能据此证明新增模块有效。正式结果需要更充分训练和同协议比较。
