## 1. 先记住整套方案要回答什么

你的思路逐渐从“预测交通状态”发展为：

> 从交通历史数据中找出当前有预测价值的节点交互，再结合长期依赖结构，在资源有限时选择值得保留的传感器和连接。

可以分成三个问题：

1. **未来会怎样？** 预测节点未来流量。
2. **哪些交互对这次预测重要？** 学习随时间变化的边分数，形成意图图。
3. **有限预算应该保留什么？** 融合意图图与因果先验，选择部署子图。

“意图”在这里经历了三种含义：时段类别 → 未来流量等级 → 预测任务相关的动态交互重要性。最后一种最接近目前工程的实际内容。它没有人类动机、车辆目的地或驾驶员变道意图的直接标签。

## 3. 第一阶段：分类与流量预测

### 3.1 最初的模型

历史窗口为 `X ∈ R^(N×W)`：N 个节点、W 个历史时刻。

```text
历史流量 → 每个时刻做 GAT → 节点平均池化
         → BiGRU 或 TCN → 一个窗口向量 z
                          ├─ 分类头
                          └─ 未来流量预测头
```

GAT 负责融合邻居信息；时序网络负责变化规律；两个任务共享中间向量。

最早分类标签由时钟产生：早高峰、晚高峰、其余时段。这更准确地叫“时段识别”。后来改成目标节点未来窗口平均流量的低、中、高等级，阈值由训练集未来均值的三分位数计算。

**未来值作为监督标签是正常预测学习，并不自动构成泄漏。** 泄漏发生在未来观测进入模型输入、预处理统计量或未经隔离的建图过程时。阈值应只用训练集拟合，验证和测试继续使用固定阈值。

这一阶段的局限在于：窗口向量主要服务一个目标节点；“分类为高流量”无法告诉你哪些节点之间的交互值得部署。这是后续转向边意图的原因。

## 4. 第二阶段：动态意图图是怎样学出来的

### 4.1 三张图先分清

| 符号 | 含义 | 来自哪里 |
|---|---|---|
| G0 | 候选图：哪些节点对允许被考虑 | 当前 DEIG 代码使用坐标双向 KNN |
| GI(t) | 意图图：这个窗口哪些交互更有预测价值 | 边评分网络，通过未来流量预测损失间接学习 |
| GC | 因果先验图：在一定假设下估计的有向时间依赖 | 外部因果发现流程导出的文件；本次没有重新估计 |

G0 决定搜索范围，GI(t) 决定动态排序，GC 提供另一种结构依据。当前意图模型不能激活 G0 之外的边。

### 4.2 数据与特征

工作区数据元信息记录：100 个节点，5088 个小时，2025-01-01 至 2025-07-31，观测量为 Total Flow。这是小时级聚合流量。

`260628` 为每个节点每个时刻准备 7 维特征：

`[标准化流量, 一阶差分, 周期残差, 小时sin, 小时cos, 星期sin, 星期cos]`。

候选边的静态特征有距离、空间方向、训练段相关性、最佳滞后及双向滞后差异。动态特征有窗口滞后相关、节点异常强度、近期趋势等。

### 4.3 可训练链路

1. GAT 在 G0 上为每个时间步提取空间特征。
2. TCN 和时间注意力把节点历史压成窗口表示 zi(t)。
3. 边 MLP 接收 `zi、zj、zi-zj、zi*zj、静态及动态边特征`，输出 sigmoid 分数 sij(t)。
4. 每个目标节点 j 的入边分数归一化：

   `s_norm(i,j) = s(i,j) / (sum_p s(p,j) + epsilon)`。

5. 用这些权重聚合源节点消息，再预测节点 j 的未来流量。
6. 预测采用残差形式：当前流量＋预测变化量。

因此，如果一条边改善了预测，预测损失可以通过消息传播反向影响它的分数。这里没有真实“意图边标签”，属于通过预测任务间接学习结构。

训练目标为：

`L = Huber预测损失 + λs·平均边分数 + λd·双向边分数乘积`。

稀疏项希望少用边；双向项抑制两方向同时很强。这只是模型偏好，实际路网可能有双向作用，应做消融后决定是否保留。

**GAT 的邻居注意力与最后的意图边分数是两套参数、两种作用。** 前者服务编码，后者直接控制后续预测消息。

### 4.4 从分数到热点

当前按每个窗口的 90% 分位数筛边，通常保留约 10% 候选边，得到 GI(t)。然后计算：

- 入分数：其他节点对该节点的预测信息贡献权重之和。
- 出分数：该节点向其他节点提供信息的权重之和。
- 活跃度：入分数＋出分数。
- 源点／汇点倾向：出分数与入分数的差。
- 热点：意图图的弱连通分量。

固定分位数意味着即使整个窗口很平静，也通常会留下相近数量的边。因此“每个窗口都发现热点”本身不能证明发生了事件。

笔记还提出边遮蔽贡献蒸馏、时间平滑、跨窗口热点匹配、逐预测步边掩码等扩展。当前核对的 `260628` 主训练目标只有预测、稀疏、双向三个部分；遮蔽主要用作评价，不能把蒸馏和完整追踪机制都算作已实现贡献。

## 5. 第三阶段：RA-TCGF 为什么要融合因果与意图

设计假设是：

- GC 提供相对稳定的依赖骨架。
- GI(t) 描述当前预测任务偏重的交互。
- 两者共同支持的边可能值得优先保留。
- GI(t) 独有的边可能是新需求，也可能是噪声。
- GC 独有的边可能在当前不活跃，但遇到故障时仍有用。

后两句是**待验证的研究假设**。仅仅把图命名为“残差热点”和“抗扰兜底”，不会自动获得这些性质。

### 一个小例子

长期图有 A→B、B→C；当前意图图有 A→B、A→D：

- A→B：两图共识。
- A→D：意图新增需求可能出现于此，也可能是估计噪声。
- B→C：当前意图较弱的稳定关系，可以测试其是否有故障备份价值。

预算不够时，门控要学会当前保留哪部分；部署后必须验证选中部分是否真能维持任务性能。

## 6. 最终四模块逐个恢复

### 模块一：七个视图和一个辅助消退视图

以下 A 均指归一化权重；MC、MI 是用阈值和温度构造的 sigmoid 软掩码。

| 名称 | 公式 | 直观作用 |
|---|---|---|
| C | AC | 提供稳定先验 |
| I | AI(t) | 提供当前任务结构 |
| CI | AC ⊙ AI(t) | 强调双方都支持的边 |
| R | (1−MC) ⊙ AI(t) | 强调意图相对先验多出的部分 |
| C\I，代码 CmI | AC ⊙ (1−MI) | 保留先验中当前意图较弱的部分 |
| P | min(AI(t), AI(t−r)) | 保留前后持续权重 |
| N | [AI(t)−AI(t−r)]+ | 提取增加的权重 |
| E，辅助 | [AI(t−r)−AI(t)]+ | 提取消退的权重，作为门控特征 |

P 与 N 满足 `AI(t)=P+N`。七张图都是少数输入图的确定性变换，并不是七个独立信息来源。它们可以帮助网络分别建模结构，但存在冗余。

CI 用权重乘积，R 用软掩码残差，所以通常没有 `CI+R=I`。不能把它们说成严格互斥、完整的集合分解。

结构统计量包括共识比例、残差比例、持续度、变化强度、新增比例和消退比例。笔记及当前代码还包含“未来延续度”，其在线可用性见第 7 节。

### 模块二：每个视图的 GNN＋TCN

每个视图输出两种表示：

- Hm(t)：每个节点的时空向量，用于局部判断。
- gm(t)：把节点聚合后的全图时空向量，用于整体判断。

当前默认：GAT 两层、GNN 隐藏维 32、节点 TCN 隐藏维 32、图向量维 32，历史长度 L=12。七个视图各有一个编码器。

**设计与实现差异：** 笔记描述每个历史时刻用自己的 Am(τ)，但 [当前编码器](<D:/Tjnu-p/Mp/Intention Recognition/260731/modules/module2_encoder.py:171>) 在整个历史窗口里重复使用同一张当前视图 A。它确实编码了历史信号，却没有完整编码窗口内拓扑序列。

### 模块三：三级门控

1. 图级 πm(t)：这个窗口整体更相信哪张视图？
2. 节点级 γi,m(t)：节点 i 周围更需要哪类结构？
3. 边级 ωij,m(t)：具体 i→j 的关系该参考哪张图？

最后联合权重近似为：

`αij,m = πm·ωij,m / sum_n(πn·ωij,n)`。

融合边分数为：

`SD(i,j) = sum_m αij,m·Am(i,j)`。

这是对已有视图边权的加权组合，不会凭空生成所有视图都没有的新边。当前节点局部统计使用入出边汇总，不是通用 k 跳 ego-graph 编码。消退视图虽进入候选与特征，但没有作为第八个融合来源直接加权。

### 模块四：预算部署

选择节点变量 pi 与边变量 qij，满足：

`sum_i ci·pi + sum_ij cij·qij ≤ B`，且 `qij ≤ pi, qij ≤ pj`。

笔记希望优化“预测效果＋故障后效果＋任务跟踪−成本”。当前实现则按 SD 边分数排序，依次纳入边及尚未纳入的端点，检查预算与节点数量限制。这是可运行的启发式选择规则，还没有求解笔记中的完整效用优化问题。

## 7. 可行性中最关键的断点

### 7.1 融合边没有从预测任务得到有效性监督——已用梯度确认

当前预测头用：

`hD = sum_m πm·Hm`，`y_hat = predictor(hD)`。

SD、节点门控 γ 和边门控 ω 没有进入预测路径。训练损失是预测 MSE＋SD 的稀疏项。见 [model.py](<D:/Tjnu-p/Mp/Intention Recognition/260731/model.py:54>)、[train.py](<D:/Tjnu-p/Mp/Intention Recognition/260731/train.py:29>)。

| 参数组 | 仅预测损失的梯度 | 完整损失的梯度 |
|---|---|---|
| 时空编码器、图级门控、预测头 | 有 | 有 |
| 节点门控、边门控 | 无 | 有，但来源为稀疏项 |
| 独立节点评分头 | 无 | 无 |

扰动边门控参数后，最大融合边变化为 0.632754，最大预测变化为 0。

复核文件：[诊断脚本](<D:/Tjnu-p/Mp/Intention Recognition/reviews/2026-09-28/probe_model.py>)、[诊断结果](<D:/Tjnu-p/Mp/Intention Recognition/reviews/2026-09-28/probe_result.json>)。

这意味着：预测准确率提高，目前不能证明局部融合边选择得更好。局部门控只有压低分数的目标，可能偏向对该边权值较小的视图。要修正，至少让 SD 驱动一次有向消息传播预测；更完整的做法是让选中节点／边决定实际可用输入，再由部署后的任务损失训练选择策略。

### 7.2 时间名义与可用时间必须分开——风险确定，具体泄漏需追溯

当前 [样本构建器](<D:/Tjnu-p/Mp/Intention Recognition/260731/dataset.py:130>) 读取 `A_I_list[c+r]`，模块一把它用于未来持续度与变化强度。

但上游 `260628` 输出的 `intent_time` 定义为**预测目标开始时间**，通常比实际输入截止时间晚一步。下游 loader 只识别 `timestamps/time_index/start_pos`，没有直接识别上游的 `input_end_t/intent_time_t`，缺省还会按末尾对齐。

所以要分别判断：

- 若 GI(t+1) 由截至 t+1 的真实观测构造，在 t 部署时使用它就是未来信息泄漏。
- 若它是截至 t 已生成、面向 t+1 的预测图，则可以在 t 使用，但记号应写成“对 t+1 的预测、信息截止于 t”。
- 离线回顾允许使用后续观测，但对应的是事后分析任务。

现有日志显示 170 张图被按末尾映射到 2025-07-24 22:00 至 07-31 23:00。这只说明读取器采取了这个映射，不证明源图本来属于这些时刻。本次没有取得该次运行对应源 NPZ 来确认，故不把“真实未来泄漏已发生”作为既定结论。

应在每张图记录 `observation_end_time`、`forecast_target_time`、节点 ID 顺序，以及生成模型的训练截止时间。

### 7.3 “弹性”指标目前无法证明故障后的任务能力

[elastic_utility](<D:/Tjnu-p/Mp/Intention Recognition/260731/main.py:59>) 随机删约 10% 部署边，计算剩余边权总和比例。它没有重新计算预测误差。

对于 E 条固定非负权重边，均匀删除 k 条，有：

`E[剩余权重 / 总权重] = 1 − k/E`。

因此这个指标期望值主要由删边比例决定；有限次抽样、边数取整和权重集中程度会使数值波动。它不能证明备份路径、断网恢复或故障后预测鲁棒性。

需要模拟边故障、节点故障、区域故障后重新执行实际任务，比较损失增加；若声称通信弹性，还需评价连通性、可达性或服务覆盖。

### 7.4 传感器部署要解决“没选中的节点还能不能看到”

当前编码器读取全部节点的历史流量。若部署意味着停用部分传感器，下一轮不应继续无条件取得所有节点的新观测。

可行的任务定义包括：

- 已安装传感器的动态启用：只观测已启用节点，用缺失值模型、缓存及少量预算内探测做下一轮决策。
- 通信调度：传感器仍本地采样，预算控制上传或通信；需说明调度器实际可以获取什么摘要。
- 固定位置选址：训练期全量观测，测试期只使用选中位置；此时“动态部署”的含义要重新限定。

统计依赖边也不自动等于无线通信链路。若 qij 真代表通信，应增加独立可通信图、距离／容量及网络连接约束。

### 7.5 因果信息经过加载后缩水

[causal_to_adj](<D:/Tjnu-p/Mp/Intention Recognition/260731/utils/data_loading.py:70>) 对因果数值取绝对值，再对滞后维取最大值。

这保留了“是否有较强关联”的信息，却丢失正负效应与具体滞后。故当前 RA-TCGF 不应描述为已经实现 baseline 3 的精细 horizon-lag 对齐。

同时需要核对：外部因果图是否只用允许的数据估计、节点 ID 是否对应、矩阵源目标轴是否一致。笔记对因果张量的轴说明，不能替代生成程序的真实约定。当前意图矩阵为 A[src,dst]；编码器的 A@X 型聚合会让源节点聚合出邻居，若设计希望下游聚合上游消息，应显式转置或使用 src→dst scatter。

### 7.6 图权重的可比性和样本量

- 意图图逐窗口除以自身最大值，会抹去部分跨窗口绝对强度变化；“新增／消退”可能混合真实变化和归一化效应。
- 七视图中 P+N=I，软残差图与原图又高度相关。分别编码可以有用，但门控权重不能直接当作唯一、可识别的机制解释。
- 当前两份融合日志只有 168 个有效窗口，默认 60%/40% 划分约为 100 个训练、68 个验证窗口，没有独立测试段。标准化使用更长前缀并不等于融合网络训练过那段所有窗口。
- 日志中的 best_val 约 0.0792、0.0810 是验证损失，不能与 DEIG 的测试 MAE 直接比较；部署导出还包含 train+val。
- 当前命令行默认数据目录仍指向旧机器的 `C:\Work-lcr\...`，并允许输入缺失时合成。正式复现需明确文件路径、关闭自动合成。历史摘要记录输入非合成，本次没有把历史运行误判为合成实验。

## 8. 到 2026 年 9 月，哪些部分新，哪些已有较多研究

下面是针对本方案的定向检索，不是穷尽式查新，也不能据此宣称“首次”。

| 相关工作 | 与本方案重合的部分 | 对新颖性判断的影响 |
|---|---|---|
| [Graph WaveNet，IJCAI 2019](https://arxiv.org/abs/1906.00121) | 自适应依赖图＋膨胀时间卷积用于时空预测 | 图学习和 TCN 的组合已有成熟先例 |
| [CaST，NeurIPS 2023](https://arxiv.org/abs/2309.13378) | 从因果建模角度处理时空预测、时间分布变化及空间影响 | “引入因果思想改善预测”本身不足以成为新贡献 |
| [DualCast，IJCAI 2025](https://www.ijcai.org/proceedings/2025/366) | 分离内在时空模式与外部非周期事件 | 稳定规律与临时变化的区分已有直接相关研究 |
| [VIP／STCV，2025 预印本](https://arxiv.org/abs/2510.24027) | 预算约束下选择 m 个输入变量，联合优化并预测所有节点 | “选部分传感器维持全网预测”已经有很接近的问题定义 |
| [NMI-IGNNK 传感器选址框架，2026 预印本](https://arxiv.org/abs/2609.13212) | 滞后依赖、贪心选址、未观测路段状态重建 | 选址、滞后信息和图重建的结合也已有相关工作 |
| [GC-MGT，2026-09-22](https://link.springer.com/article/10.1007/s44163-026-02230-y) | Granger 预测依赖先验、神经修正、状态相关多图融合及仿真干预评估 | 因果先验＋动态多图融合已有近期直接对照 |

以上论文方法与本工程并不完全相同；这里比较的是任务和机制重合程度，不是认定你的方案被某篇完整覆盖。预印本也不等同于已经通过同行评审。

**判断：** 继续做普通流量预测、再增加几个 GNN/TCN/门控模块，创新空间较有限。更有针对性的研究问题是：

> 在只能观测部分节点、关系会变化且传感器可能故障时，如何利用稳定先验与任务依赖之间的分歧，选择预算内的观测集合，兼顾预测质量、故障退化和切换代价？

这需要把“残差有用”“稳定图能兜底”变成可被实验否定或支持的假设。当前结果尚未证明这些假设。

## 9. 最值得保留的主线与最小验证顺序

建议保留“预测驱动的动态图 → 稳定先验补充 → 预算选择”主线。先解决三件事：

1. **统一时间和观测协议。** 图何时生成、使用什么历史、何时做部署、部署后能看到什么，都明确到时间索引。
2. **把选择结果接到实际任务上。** SD 控制消息传播，节点选择控制观测掩码；关闭传感器时同时处理所有特征和编码路径，防止从其他支路取回被关闭节点的数据。
3. **先用少量视图证明互补性。** 比较因果图、意图图、简单融合、共识／残差分解，再决定是否需要七视图和三级门控。

最小实验矩阵：

| 问题 | 比较设置 | 核心观察 |
|---|---|---|
| 动态意图是否有用 | 全量预测、静态图、动态意图图；多随机种子遮蔽 | 原单位 MAE/RMSE，分预测跨度报告 |
| 因果先验是否带来信息 | 无先验、真实先验、随机化先验；训练段内估计 | 同等复杂度下的增益，先验错误时是否退化 |
| 残差分解是否有价值 | 简单加权、两图门控、少量残差视图、七视图 | 正常期与异常期分别评价 |
| 同预算能否选得更好 | 随机、地理覆盖、度／权重排序、学习选择 | 固定预算下全网预测与覆盖 |
| 所谓兜底是否成立 | 随机边失效、节点失效、区域失效 | 故障后的任务误差与恢复能力 |
| 动态部署是否值得 | 固定子集与动态子集 | 误差—预算曲线、切换次数／成本、推理时延 |

所有对照使用相同观测权限、目标时间段和可比预测器。先验与意图生成器的训练过程也必须隔离测试段；如果采用滚动更新，每次只能用当时已观测数据。历史输入跨越划分边界在滚动预测中可以合法，重点是预测目标、模型拟合及预处理不能使用未来。

## 10. 一段适合你重新讲给别人听的概述

> 我们研究交通传感网络中的任务驱动观测选择。首先，用历史流量训练一个时空图模型，让有向边分数参与未来流量预测，得到随窗口变化的任务依赖图。然后，将这张图与长期估计的因果先验比较，区分共同支持、当前额外激活、先验暂未激活及持续变化的结构。模型根据全局与局部状态融合这些结构，并在节点和边预算下生成子图。研究要验证的核心，是这种结构分歧能否帮助系统在部分观测和故障条件下，更有效地分配传感资源。

目前最有依据的是前半段动态依赖学习；后半段需要补齐“部署选择改变可用信息、任务误差反过来训练选择”的关系。方向可以继续，现有证据还不足以把完整系统写成已经验证的前沿方法。
